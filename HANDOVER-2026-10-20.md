# GoalBrew: handover for a new chat (20 Oct 2026, updated 22 Oct)

Read this first. It replaces the older notes in HANDOFF.md (1 Oct), which are out of date.

## What it is
- **GoalBrew** turns InPlayGuru (IPG) football alerts from Telegram into graded picks, and places the Live ones on Betfair itself ("direct betting").
- **Engine** `apps/` (Node/TypeScript, SQLite backed up to a DigitalOcean Space). **Website** `apps/web/` (Next.js, admin area under `/more/admin/...`).
- **Repo** `surge-bot`. Every push to `main` deploys to DigitalOcean App Platform: https://seashell-app-z8xl5.ondigitalocean.app (takes ~5–8 min).
- **Every push restarts the betting engine, website-only changes included** (the engine's folder `apps` contains the website). Each restart means ~2 minutes without alerts (it waits 90 s for the old engine to let go of Telegram). **Batch changes into few pushes, outside match hours.**
- **Checks before a push:** `cd apps; npx tsc --noEmit -p .; npm test` (391 tests) and `cd apps/web; npx tsc --noEmit -p .; npm test; npx next build`.
- **DigitalOcean sometimes misses a push** (twice on 21 Oct: nothing in its Activity list). If the site hasn't changed ~12 min after a push, check cloud.digitalocean.com → seashell-app → Activity (the user signs in); if the commit isn't listed, Actions → Deploy (with the user's OK). It usually catches up.
- **Is it live?** The website's build id is in the `/members` page (`"b":"…"`); `/more` redirects, so don't watch that. Engine checks need the admin signed in in the browser, then `fetch('/api/admin/...')`. `/api/admin/today` and the reports carry `timings` (ms per part).

## How the user works (important)
- Non-technical. Plain English, no terminal steps for them. Explain money effects clearly.
- **Push only when they say "push".** Real-money settings only on their explicit instruction.
- Never type their passwords or card details; they sign in themselves (GoalBrew admin, InPlayGuru, DigitalOcean, Betfair).
- **Never script-click every button on the live admin site.** A test sweep once switched automatic stakes off (restored). Only test expanders/view switches, and check `/api/admin/sending` before and after.
- Always pull and edit the latest files; never paste in a whole file from an old copy or another chat (commit `691b792` once undid recent work that way). If a deploy fails, diff the latest commit against the one before and look for removed lines unrelated to its purpose.
- Don't run the real engine locally. API-Football: stay within 100 calls/day. Avoid empty `python -` heredocs (they hang); write script files.
- Members (free 7-day trial) can never touch bots or Betfair; selling/prices are hidden.

## Main features (where to find them)
- **Admin menu:** Today · Strategies · Betting · **Golden** · then More (Profit, Leagues, Members, Settings, Fix a result, Horses).
- **Strategies:** opens on **Weekly** (one row per strategy, £ per week from the first week with data, last 7 days, trend label; "↳ of which Golden" rows are part of the strategy, never extra). **Cards** view: tidy card; tap for details, bet settings, "Bet Golden alerts separately" box.
- **Golden** (`apps/src/server/segments.ts`, `golden.ts`; page `web/app/(tabs)/more/admin/(protected)/golden`): watched slices (candidate until 50 priced picks since start, then Golden or "not holding up"), each counted from its start date only; **Golden finder** suggests new slices every 6 h (must beat the rest in both halves of the record); "Watch it" adds a custom slice from today (setting `custom_segments`); slice betting in Sending settings `segmentBets` ("strategy#slice": live, stakePct, liveSince).
- **Live tab:** Live/Sim/All filter; Golden alerts have a gold edge, badge and a line saying what happens to them; "Bet this for real" on fresh Sim picks (hand bets stay in the strategy's Sim record and out of its Live judgement).
- **Today:** suggestions (Put Live / back to Sim / stop in a league; stake steps are automatic so shown as dated "next steps"), why picks weren't placed, speed.
- **Leagues → Profit:** money by league/country/tier and strategy within a league, milestone notifications at 50/100/250/500 priced picks, "Stop it here" for a strategy in a league (100+ picks).
- **Results fallback** (`fixtures/result-fallback.ts`): an alert still without a result 4 h after kick-off is settled from API-Football's final score (already fetched for goal times: no extra calls), normal-time finishes only, never below the alert's own score; stored with `score_source` = api-football, and IPG's own full-time edit still replaces it.
- **Phone widget** (KWGT): ready-made preset `apps/web/widget/GoalBrew-Today.kwgt` (rebuild with `python widget/build-kwgt.py`), left half refreshes, right half opens Today; the user pastes the widget address into the `gb` global after import (the key isn't in the file). Guide: `apps/web/WIDGET.md`.
- **Profit, Dashboard, Trade Log** all price picks the same way (`apps/src/server/pricing.ts`, `winloss.ts`). Betfair's settlement corrects a pick's result when GoalBrew's own bet disagrees with IPG's score.
- **Horses:** results logged from Betfair automatically (`horse-results.ts`): every 3 min 10:00-23:00 UK a new bet is matched to its race (a name the tipster misspells by up to 2 letters is matched within its own race: course + tip time), and its result is looked for from 5 min after the off until settled. A horse that can't be found gets one notification ("mark it by hand"). Win bets are logged "placed" when the horse placed (the single still loses; the day's EW Yankee counts the place). Only pending results, odds never changed.
- **Matched odds home** (IPG strategy): GoalBrew market HOME_TO_WIN (Match Odds, home team; a draw loses). It fires at 0' because the IPG rule has no minimum minute; the user may add one in IPG.
